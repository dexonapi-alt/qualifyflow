# ADR-0006 — Real management sections and compact account summary

Accepted 2026-11-17 for the existing M1 information-architecture refinement and subsequent overview-summary steering. Preserve the shell, fonts, palette, motion, authorization and backend contracts from the preceding work.

Reuse CompanyWorkspace for the single-company Client Portal instead of maintaining a separate overview implementation that redirects into a second management screen. Embed the workspace after the existing page title/breadcrumb. Its functional section navigation is Overview, Locations, permission-gated People & access, Configuration and existing authorized audit/service sections. No new business endpoint is required.

Overview uses a compact 2×2 definition-list summary for service mode, effective date, current role and access scope. These are actual metadata, not KPI cards or legal-compliance statistics. Below, group company details, setup/activation context and real quick actions. Compact company identity/status remains below the navigation without competing with the page title. This is the owner's explicit correction to stretched metadata rows; it does not authorize dashboard-card wallpaper.

Locations displays the already-scoped branches returned by GET tenant detail, with real loaded-record name/reference search. Only company-wide managers in writable states receive the existing Add branch form. People/member/invitation and audit history use semantic operational tables, preserving real mutation handlers, reasons, versions and confirmations. On narrow screens, record tables can scroll inside labeled keyboard-focusable regions without overflowing the whole page.

Configuration is structured read-only information for client roles and the existing actual responsibility/activation controls for service administrators. Detailed readiness blockers remain service-admin-only as the API currently defines. Navigation never grants a capability. Audit remains limited to permitted company-wide grants. Show real pending/loading states while section data is fetched.

No M2–M6 feature, font, palette, dependency or backend rule is introduced. M2 remains the next engineering milestone.

Summary-card paragraph superseded by ADR-0007 after explicit product-owner rejection. Shared management navigation, operational tables and permission/data boundaries remain accepted.
