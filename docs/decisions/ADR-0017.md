# ADR-0017 — A cohesive managed-service product experience

2026-11-17. Owner's BEST DESIGN.webp reference was visually inspected. Latest direction explicitly resumes browser, regression and accessibility verification, superseding the earlier testing pause. Previous unverified M2/M3/M4 implementation must be audited, not hidden by new visuals.

Design principles adopted: continuous white sidebar/workspace, compact useful header, precise contemporary typography, soft shallow surfaces, contextual record tables, real people/ownership and differently structured supporting information. No copied project/calendar widgets, invented activity or dummy metrics. Owner-specified palette supersedes older proposed selection/status styling: selected navigation #2f63e3/white; pending #e9a0e8, work in progress #9ff2a4, completed work #6a90f7. Charcoal labels pass contrast on these surfaces; errors/expiry retain distinct warning/error semantics and readable labels. Completion describes a particular record/review/action, never legal compliance.

Information architecture follows responsibilities: clients get a company overview, drivers/onboarding, requests and decisions; specialists get their client-scoped work, screening inbox, reviews, cases and follow-up. Company configuration/requirements remain accessible administrative tools. Existing authorized routes are reused, with selected-client context and no duplicate operational tabs inside company settings.

Introduce a role-aware overview fed by real scoped database aggregates, driver records, current service-team assignments, outstanding recipient actions and recorded activity. No assigned requirements means no progress percentage. Unassigned work is explicitly unassigned; a received item is not reviewed/completed. No grant means no protected aggregate or report detail. Provisioning-only administration stays metadata-only.

The header returns as a useful control surface: actual client switching, real scoped driver search, existing requests and authenticated account controls. This supersedes the earlier ban on a redundant sign-out-only top strip. Account/session behavior and backend permissions remain intact. Reference resources support token layering and dense enterprise composition, not replacement of QualifyFlow's identity or stack.
