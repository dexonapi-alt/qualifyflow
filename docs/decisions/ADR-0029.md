# ADR-0029: Per-row bulk corrections with durable replay

2026-11-19. Owner requested the next M3 implementation after saved mappings. This extends Document 01 §4.4 and Document 03 §9.5–9.6 without modifying original specifications or claiming milestone/release completion.

Specialists need to correct multiple source rows without discarding a whole handoff or silently overwriting history. Add a maximum-25-row preview/confirm operation against one existing receipt. Each selected item supplies the five canonical metadata fields; a verified basis is recorded with every successful replacement. The exact single-row validation/write service is reused for both paths, preserving immutability, duplicate protections, lineage limits, current authorization, case-version invalidation, explicit match requirements and evidence gates.

Preview validates without creating receipts, corrections, runs, jobs or acceptance records. It identifies ready/blocked/unchanged rows, including collisions between proposed report/type keys. Confirm revalidates current state under the tenant lock. Per-row transaction savepoints retain valid replacements despite ordinary row validation failures. Authorization/scope failures abort rather than being converted to normal row results. All selected IDs must belong to the exact authorized source receipt before any write; duplicate selections and oversized requests fail validation. Unexpected database errors roll back the outer transaction, including all replacements.

Migration nov19006 adds append-only `intake_correction_runs`: tenant/source batch/actor/command, request hash, encrypted rationale/attempted values/results and creation time. Deterministic per-row commands derive from the root UUID and stable source ID. The outer transaction commits both replacement receipts and the durable result envelope. Repeating the same command returns recorded outcomes; changed input conflicts. A new command can retry remaining failed rows after correction, while used/superseded originals remain protected. Concurrent same-command requests serialize to one run. The synthetic bound is 100 runs/company; history returns the most recent 20 runs per source receipt.

Endpoints: POST `/api/v1/tenants/{tenant_id}/intake-batches/{batch_id}/correction-runs/preview`, POST/GET `/correction-runs`. Existing drivers:write inbox access governs reads; current administrator/specialist/reviewer correction authority governs writes. Branch restrictions, tenant suspension, membership revocation and provisioning-only isolation remain unchanged. No report upload, legal decision, reviewed-match reassignment or automatic case closure is introduced.

UI: receipt selection, bounded bulk toolbar, native detail-panel editor, explicit outcome preview, persisted partial-result summary, replacement links and expandable run history with actual actor/basis. Original metadata is not placed in editable-looking bubbles outside the correction editor. Keyboard/44px selection targets, scoped table scrolling and reduced-motion behavior remain. Ordinary values remain text; color supplements outcome labels.

Deferred: corrected-CSV reupload with stable row identity, cross-receipt operations, automatic transformations, bulk driver match/reassignment, asynchronous larger imports and remaining M3 exit evidence. The existing single-row API and saved-mapping contracts remain compatible.
