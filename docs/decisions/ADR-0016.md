# ADR-0016 — Client-approved in-app correspondence

The specialist role needs actual client follow-up, not an awaiting-client label alone. Add a versioned client process that names one current whole-company employer administrator as the approved in-app recipient and records approved instructions. Only a current employer administrator can configure, revoke or supersede this process. No fallback recipient, automatic email or external outbound channel.

An exception owner drafts an information request against the exact case version and approved policy/recipient. The immutable text is pending approval until a current employer administrator explicitly approves it. A durable database queue publishes into the authenticated recipient's inbox only after rechecking current sender/approver/recipient authority, tenant state, policy version and case version. Source/version changes suppress rather than silently retarget a request. Sent means available in the portal; opened and responded are distinct recorded events. Replies preserve the case history and return an awaiting-client case to review without changing evidence or eligibility.

This is an actual in-app channel, not a commercial email integration. Reminder schedules, multi-recipient policies, email provider delivery/bounce/reconciliation and approved external communications remain separate work. Existing testing pause is respected; implementation is not release verification.
