# ADR-0028: Reusable, scope-bound spreadsheet mapping revisions

2026-11-19. Owner requested the next implementation after ADR-0027. Continue M3 with saved column mappings; no milestone or production-readiness claim and no original specification changes.

Recurring handoffs should not require rebuilding the same five-field map. Save a named mapping from an actual mapped receipt, preserving its source batch, location, column names/order, positional map, author, rationale and creation time. No driver values, workbook bytes or accepted outcomes are copied into a template. Configuration is encrypted. `intake_mapping_templates` (migration nov19005) has append-only database protection, unique logical-template revisions and unique per-actor command IDs. Revisions and retirements append new records rather than changing prior snapshots.

Current intake permission (`drivers:write`) is required to list/reuse configurations, matching the existing protected inbox boundary. Client administrators, assigned specialists and reviewers may save/revise/retire; contributors may reuse but cannot manage templates. Provisioning authority alone grants no access. Exact selected location applies, including whole-company versus branch scope. Tenant locking serializes updates and retirement; stale expected revisions return conflicts. Save is bounded to 100 persisted mapping revisions/company in this synthetic implementation; retirement remains possible when that save quota is reached.

Reuse is explicit. Both preview and receipt creation verify the latest active revision, exact location, exact header names/order, and the selected map. A changed layout requires manual mapping; there is no fuzzy or positional guessing across changed layouts. Refreshing or editing mapping fields does not invent acceptance. Manual mode removes template binding and requires a new preview. A template revised/retired between preview and receipt causes a conflict. Already-recorded receipts remain readable and preserve the exact template revision/name/version they used; successful command replay returns the existing receipt rather than retrospectively invalidating it. Requests without a template preserve the prior command fingerprint contract.

API: GET/POST `/api/v1/tenants/{tenant_id}/intake-mappings`, POST `/{template_id}/retire`, plus optional `template_revision_id` on mapped preview/receipt. No new dependency, driver/evidence permission, provider endpoint or outbound message. Existing explicit match, real scan, evidence review and employer decision gates remain.

Deferred: mapping transforms/category aliases, standalone revision comparison/history browser, cross-location sharing, reactivation, bulk correction, asynchronous large imports and remaining M3 exit evidence. This slice is a reusable-column-layout facility, not an approved compliance rule or automation policy.
