# ADR-0030: Bounded background spreadsheet imports

2026-11-20. Owner requested the next M3 slice after bulk corrections. Extend Document 01 §4.4 and Document 03 §9.5–9.6 while retaining the original small synchronous import/API contracts. Original specifications remain unchanged; remaining milestone and production gates are open.

Use a separate durable workflow: receive private source → queued inspection → awaiting mapping → queued validation → awaiting explicit confirmation → record receipt parts → completed. Failed and canceled states preserve the original source and any committed receipt parts. Completion means metadata outcomes were recorded, including invalid/duplicate rows; it is not driver matching, evidence acceptance or a legal decision.

Migration nov19007 adds immutable encrypted `spreadsheet_import_sources`, mutable leased/versioned `spreadsheet_import_jobs`, and immutable `spreadsheet_import_parts`. Source retains uploader, tenant/location, command fingerprint, SHA-256, private file bytes and metadata. Part links bind source data-row ranges to actual existing intake receipts. Job state holds encrypted parsed/mapped/preview snapshots, attempts, version, lease and committed-row cursor. Source/part database triggers reject updates/deletes. Cancel stops remaining work; it does not delete the source or reverse committed parts.

Bounds: CSV/XLSX up to2,000,000 raw bytes,1,000 selected-sheet data rows,32 columns/five sheets,128 archive entries,8MB expanded XLSX and1.5MB canonical metadata. Twenty background sources/company is the local synthetic quota. Real antivirus must clear XLSX before hardened XML/Office parsing; existing formula/macro/external-link/archive checks remain. CSV is bounded UTF-8 metadata, never executed or rendered as file content. Ambiguous numeric Excel identifiers become individual invalid metadata rows; valid text identifiers preserve leading zeros. No numeric/name guessing or automatic driver creation occurs.

A dedicated native `app.screening_intake.import_worker` keeps slow workbook inspection separate from document scans, messages and case routing. Celery registers the same handler. Five-minute leases, token checks, current uploader authorization before/after external I/O and tenant-first locking prevent stale workers from committing after cancel/revocation. Ordinary phase failures require explicit bounded retry; leases recover interrupted workers. Unreadable encrypted sources become recorded failures rather than poisoning the queued claim loop indefinitely.

Confirmation records parts of at most50 rows and less than60KB canonical text, reusing existing receipt validation/deduplication and durable intake jobs. Each part, source-range link and cursor update commits in one transaction. Deterministic commands derive from source ID/offset; a failed part rolls back without losing earlier parts. Preview detects duplicates across parts and existing scoped receipts. Final recording revalidates current state. Original workbook provenance stays linked to every part; mappings can be saved from recorded parts. Background receipt evidence paths require the existing explicit reviewed driver/engagement match.

Uploader or current administrator/assigned specialist/reviewer controls an import. Contributors may view authorized intake metadata and control their own uploads; they cannot control other people's imports. All reads/writes remain tenant/location scoped; provisioning and viewer authority do not grant intake access. The original uploader must retain current processing permission, even when staff configures a mapping. Saved mappings are rechecked during validation, confirmation and every recorded part. A mapping retired after partial recording stops remaining work; committed parts stay intact. Reconfiguration after confirmation is forbidden.

API: GET/POST `/api/v1/tenants/{tenant_id}/spreadsheet-imports`, GET `/{import_id}?offset=…`, POST `/{import_id}/mapping`, `/sheet`, `/confirm`, `/retry`, `/cancel`. Upload/queue actions acknowledge durable pending work, not processing success. Preview pages contain25 rows. Version checks protect current user actions; repeated confirmation returns the existing confirmation. No raw-source download/public URL or external integration was introduced.

Deferred: production object storage/retention, larger quotas, independently measured throughput/fairness, machine alerts, approved transformations, corrected-CSV reupload and reviewed reassignment. Existing M4–M6/security/commercial release evidence remains required.
