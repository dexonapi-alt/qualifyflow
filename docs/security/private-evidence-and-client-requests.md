# Local evidence and client-request boundary

Synthetic local development only. Settings still disables staging/production. New controls are implemented but unverified while tests are paused.

- Evidence objects use random immutable keys and encryption with the configured application key. Local private storage is outside static frontend serving; every download rechecks current tenant/driver/engagement/requirement authorization, verifies integrity and records an audit event. Never rotate the encryption key without a migration/recovery plan; back it up separately with the database/object store.
- Original evidence metadata is protected by a database immutability trigger. Definitions, assigned requirement snapshots, reviews and intake attachments are append-only. No delete/retention override is provided; approved retention/hold handling remains future release work.
- Uploads are bounded to PDF/PNG/JPEG signatures, 2 MiB, 50 pending scans and 1,000 local evidence versions per company. This is not a claim of full structural parsing or an enterprise load target. Private encrypted orphan-object reconciliation after a database/storage failure remains an operational task.
- Windows uses actual Defender custom scanning with remediation disabled. Linux uses a configured local/internal ClamAV INSTREAM endpoint. No successful scanner result is simulated. Unavailable/error/integrity failures remain quarantined; retry is authorized/audited. A dedicated native scan worker avoids blocking intake and in-app requests. Scanner execution has not been verified in this iteration.
- Native default PRIVATE_OBJECT_DIR is ../.local/evidence from backend. Compose API/worker share a private-evidence volume at /var/lib/qualifyflow/evidence; the existing MinIO service is not claimed as connected. Production S3 and a provisioned ClamAV daemon remain required deployment work. Docker/scanner availability has not been verified.
- Browser downloads are authenticated attachment responses, never public permanent object links or untrusted inline previews. Private source filenames/checksums/content never enter ordinary audit details. Scope-aware sensitive-event filtering is preserved for provisioning-only roles.
- In-app requests bind immutable text, source case version, client process revision, recipient and author. Current employer administrators configure/approve; the worker rechecks current authority before publishing. No external transport or recipient fallback. Sent/portal availability, opening and response are separate records. Version changes suppress or invalidate stale approval authority.
- All request/reply text and event content is encrypted at rest and rendered as escaped text. Client replies never imply evidence acceptance or legal eligibility. New related evidence/replies invalidate case-version decisions; cases are not silently resolved.

Pending verification includes tenant/branch attacks, wrong-driver/requirement/source attachment, scanner failures/timeouts, signature/size abuse, idempotency/concurrency, immutable source tests, revoked recipients/approvers, stale content/process/version rejection, real browser/MFA journeys, keyboard/reduced-motion/contrast and isolated test-object roots. No such pass is asserted here.
