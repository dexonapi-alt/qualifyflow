# Specialist workflow alignment

Owner feedback: modules existed in both sidebar and Company access tabs, each lacked a clear task boundary, and the main job workflow remained incomplete. ADR-0015/0016 record the correction.

Operational modules now have their own page title and company context. Company tabs contain administration only. Actual opaque-ID routes support refresh/back navigation; no driver names/report contents enter URLs. Requirements and File review are working destinations with actual grants, not placeholder modules.

The core composition follows the specialist's job: receive a spreadsheet → inspect row outcomes → open the exact-reference driver file → assign a configured requirement → upload private evidence → wait for actual scan → inspect and record review → follow up from a case under the approved client process. Repeatable work uses compact tables, real record initials, semantic labels and contextual actions. Client correspondence uses readable multiline text and versioned request/response history. No fake charts, metrics, staff or progress percentages.

File review computes attention from assigned current-engagement requirements and actual evidence/reviews. It does not invent regulatory completeness. Ordinary Company access remains an administrative workspace rather than duplicating module navigation.

Original font, palette, white canvas, icon proportions and restrained motion remain. File/message symbols extend the same native icon family. New responsive styles use stacked file/review controls and scrollable semantic tables, but rendered visual QA has not run because testing remains paused. No screenshot quality or accessibility pass is claimed.
